# V5 track waveforms

Waveforms show the **original PCM envelope before position, mixer and FX**. Each of 128 display bins covers a fixed part of the source/capture window and contains the true minimum/maximum across its mono/stereo channels. These are display bins, not an assumed AudioWorklet quantum. The drawing uses scale ±1; an overrange peak is disclosed while original PCM remains unchanged. Unreceived bins stay empty. A partial bin includes only samples actually received.

During capture, the UI requests only the newly acknowledged prefix through a read-only handle. It reads existing validated capture buffers, then the immutable TakePool after adoption; no writable original or full raw copy is exposed. Once complete/partial, the same waveform remains with truthful take state. Recorded project clips derive their waveform from a hash-checked local Blob, without an AudioContext or microphone. Waveforms survive project reload by being derived again; no project/export schema field is added. Phase, mute, pan and EQ do not alter this original-source picture, as the caption explains.

UI metadata is reserved against the existing AudioMemory budget: 16 KiB per cached source/live summary and view allowance. Canonical project limits bound references to 128 and tracks to eight. Original Blob reads are serialized and reserve `2 × raw bytes + 8192` transiently; no cache of full PCM is added. Read failure shows a retryable unavailable waveform, never fabricated silence or an audio edit. Discard drops a live summary; project replacement prunes unused sources. Navigation/pagehide aborts pending reads and releases owned summary leases. The 64 MiB root budget is unchanged. This is ledger accounting, not a claim about total browser/DOM RSS.

The cache binds SHA256, recording rate, channels, frame count and encoding. The same bytes can validly describe stereo N frames or mono 2N frames; importing that different layout invalidates the old summary and releases its lease. Compiled UI acceptance imports both layouts and checks every bin before restoring stereo. Session-take summaries use the immutable take object identity, so an ID reused by a replacement pool cannot alias an earlier take.

Acceptance: `qa-artifacts/v5-profile-waveform-2026-10-17`. The final compiled app exercises profile workflows, source waves before gesture, growing native capture, full/partial states, adoption/IndexedDB reload, playback/mute/Stop/Resume and recovery. All received native PCM is retained losslessly for the waveform oracle. Independent numerical recomputation checks every sample's bin and every rendered segment, with only preset three-decimal SVG display quantization allowed. No fit, excluded frames or invented unreceived suffix. This is a writer audit, not peer-review acceptance or physical listening.

The first waveform UI attempt found that progress was gated on a terminal outcome. The corrected handle exposes live acknowledged-frame count before outcome publication; a regression and a fresh compiled UI run qualify it. Earlier failed attempts remain retained. Actual microphone/device latency, acoustic response and musical quality remain unverified; these waveforms are not an automatic calibration measurement.

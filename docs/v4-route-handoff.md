## Single per-tab editable project, explicit routes

The opt-in preview opens Stage at `/gamelan/` or `/en/gamelan/`. Its new route panel offers a confirmed move to `/studio/?workspace=gamelan&lang=id` or `/en/studio/?workspace=gamelan&lang=en`, and back. The exact same canonical schema4 project is retained, including complete legacy `composition`, original `origin.text`, event IDs/ticks/action/velocity, bank versions, mix and tuning consent. It is never flattened to schema3, a waveform or MIDI quantization.

The existing combined editor/InstrumentSession/Transport/renderer is used in the Studio route. `src/main.js` selects it **before initializing the legacy Studio controller** only in `gamelan-preview` mode and with the explicit query. A normal Studio route, or any default/production build even with this query, continues using the legacy schema3 controller. That controller never reads the new route key. Preview Studio HTML has noindex even before JS; the specialized schema4 editor needs JS. No-JS retains the existing Studio shell, without pretending schema4 is playable.

Language is explicit in the destination URL; no project data/IDs are put into the URL. Credits can return to the routed Studio view. History Back/Forward and reload read the tab's **latest** accepted project rather than replaying a pending transfer copy or restoring an older source. The bfcache/persisted-pageshow handler reloads the disposed document so an old owner cannot revive. Editor undo/redo histories start fresh on navigation; current edits and musical data survive. This is a paused handoff, not a seamless live-performance switch or a persisted playback cursor.

## Storage and recovery contract

`InstrumentRouteStore` owns only sessionStorage key `perkusi.workspace.instrument-route.v4`, a strict3MiB metadata envelope: version1, revision, schema4 project, and one nullable pre-transfer source snapshot. The project retains the existing1MiB validation limit. Source snapshot updates only when a transfer is confirmed; it is not an unlimited history. No PCM/audio/file paths are stored. Data belongs to this tab and may disappear on closing/clearing it; UI directs the user to save a browser project or download a backup first.

The existing global schema4 saved-project library is still available, while its automatic draft writer is replaced by this per-tab store on the opted-in routes. That prevents one tab's autosave from replacing another tab's route project. Old shared browser Gamelan drafts are not silently adopted; an explicit confirmed read-only-copy action makes them accessible without overwriting their original record. Saved library copies remain shared across tabs under the pre-existing store's retention/limits. This slice does not claim a new cross-process transactional guarantee for simultaneous shared-library saves.

Every project reference change is saved immediately in route mode (no350ms debounce), then confirmed by readback. Legacy1/2/3 draft/project/transfer keys are never written by this store or this controller. Writes compare the entire last observed raw record; stale/reentrant/same-tab writers refuse rather than rollback over a newer record. SessionStorage is per tab; a new-tab link uses `noopener` so it does not silently inherit the source tab's draft. A deliberately duplicated browser tab can inherit a copy initially by browser behavior, but subsequent stores remain physically independent.

If initial reads fail, recovery of access must **not** let an empty or unsaved in-memory project overwrite an unseen saved record. Repeated writes refuse until the user deliberately loads the latest draft. Invalid/future/oversized/corrupt records are retained. Recovery actions provide current project backup, original raw tab-data download, the last pre-transfer source, explicit latest-draft load, or a fresh noopener workspace where a valid project backup can be imported. No automatic clearing/eviction is added.

Transfer confirmation validates/persists the complete current project+source snapshot in one record, flushes pending draft status, releases project-download output and awaits session disposal before assigning the URL. Recording/replay/loading/export/sharing/other mode transition blocks this action; the user must finish/pause first. Cancel before confirmation changes neither record nor project. A failed prepare/readback keeps the URL and current project; it never claims destination success. An unconfirmed native write, including a silently dropped write, fails. An exception after a write can count as committed only if readback confirms the exact intended bytes.

An autosave failure retains in-memory edits and warns on browser navigation/close via beforeunload when supported after a gesture. User cancellation keeps the document/edit; an acknowledged retry saves before leaving. Browser crashes, power loss, ignored beforeunload and closed-tab durability are not guaranteed. Explicit transfer cleanup failure retains the saved project and source page; existing close/release cleanup is retried without reviving the terminal owner, and the UI directs reload. Persistent native cleanup failure must remain an honest unresolved resource state, not a claimed successful navigation.

## Audio/privacy boundaries

The only audio source changes in this slice are disposal finalization in `AudioEngine` and `InstrumentSession.closeAudio`. A native `AudioContext.close()` rejection is retryable only after all earlier bank, voice, capture and graph cleanup completed. Retry is serialized and cannot make the terminal engine playable; an earlier cleanup failure cannot be masked by this path. Native injected-close failures exposed the defect, and the original failing evidence is retained alongside the passing fix.

A new route starts with no live AudioContext/autoplay; project playback/export still uses immutable sources, original tempo/PPQ/event positions, full available tails, group mix/consent and the same renderer. The source owner pauses/stops/closes on leaving; no AudioContext or buffer is transferred between documents. Physical continuity, latency and actual speakers are unverified. Metadata moves only through browser storage; there is no upload, cloud project link, backend or paid API. Existing analytics gate remains local-off/production-only and sends only aggregate names/validated enums; the successful cross-route Studio event follows cleanup, not a failed/cancelled attempt.

Native decode profile is negotiated again when destination audio is explicitly enabled. Before that negotiation, a cold destination retains the existing48k export default; the source document's44.1k context does not silently create a destination context. A44.1k export check therefore enables audio at the destination and verifies its actual rate before comparing the complete output to the accepted44.1k oracle. This does not alter project musical data or source PCM.

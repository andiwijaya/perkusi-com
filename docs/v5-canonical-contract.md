# V5 canonical contract, revision Q1c.a

18 October 2026. Technical completions requested in `qa-artifacts/v5-unified-independent-2026-10-18/MIGRATION-REVIEW.md`. Supersedes the incomplete wire shape in the sealed Q0 proposal; the Q0 packet/build remains immutable. Owner scope already covers these V5 features. Format revision 6 is not product V6. No route, old parser, store or renderer is switched by this document.

## 1. Wire shape and ownership

Exact envelope keys: `format, schemaVersion, mode, title, timing, master, tuningConsent, transport, activeSection, tracks, sections, chain, sourceDefs, origins, assets, compatibility, export`. Values `format:"perkusi-project", schemaVersion:6, mode:"composition"`. Unknown keys/versions/ref cycles/duplicate IDs reject, never get discarded. All records are plain data; reject getters before reading values. Reject byte/structural limits before copying/expansion. Root `tuningConsent` preserves schema5's independent outer consent (default false); native score consent remains in its own programme. Schemas0–4 use false for this non-legacy outer field, and cannot project a new true value silently into an old file.

`timing={bpm,meter:[4,4],clock}`; clock is `{kind:"musical",ppq:960000}` or `{kind:"fixed-bar",sampleRate,framesPerBar}` using the exact old rounded capture geometry. Swing/quantize are source-programme fields, not a second global tempo. `master={volume,limiter}` uses existing limiter version1/kind soft-knee-v1. Missing old limiter becomes the existing bypass preset, never a new gain stage.

Canonical outer volume is0–1; original0–4 master validation remains0–0.75, schema5 outer master0–1. Group local master retains its old0–0.75 bound. A future root edit above0.75 cannot be projected back to schema0–4 without an explicit conversion decision. Zero, custom and maximum accepted values are never replaced by the blank-recording default.

`tracks[]` are **outer mix buses**, not flattened instrument roles. Exact `{id,kind,name,mix,fx,layering}`; kind `group|recording|hybrid`, mix `{volume,pan,mute,solo}`. Each bus may host group and/or audio placements consistent with its kind. An imported Loop event bus maps to group; its recording/hybrid kinds remain recording/hybrid. No source or audio is duplicated merely to display sublanes.

`sourceDefs[]` are working editable score identities; origins are immutable bytes/text. Common keys `{id,kind,originId,workingOriginId,parentId,master,programme}`. IDs are stable within a document. `originId` binds original source content; `workingOriginId` binds exact schema5 working `sources[].text` when present, otherwise null. Old `sources[].originId` and current working text remain distinct even when their contents differ. `parentId` null except an instrument score's composition accompaniment. `master={binding,volume}`: binding `project` (volume null, use envelope master), `local` (finite old source volume), or `parent` (volume null, inherit the parent score bus with **no second DSP multiplication**). Root schemas0–4 bind their source master to project; schema5 retains outer master and each referenced source's local master. The source's original master is recoverable from the explicit binding, not duplicated and silently multiplied twice.

### Composition programme (kind `composition`)

Exact programme keys `{title,pack,timing,percussion,bilah,clipPack,patterns,activePattern,chain,export}`. Pack, timing/swing/quantize, export, original kit and processing revision use existing validated values. `percussion` holds the eight original `{role,volume,pan,mute,solo}` rows. `bilah` is the existing `{id,version,volume,pan,mute,solo}`. `clipPack` preserves all current id/version/bpm/bars/key/processing fields.

Each pattern is `{id,name,steps,notes,beatbox}`. Steps are all eight roles ×16 velocity cells; notes are the original sixteen null or `{pitch,velocity}` cells. `beatbox` contains exactly six role controls `{role,enabled,variant,volume,pan,mute,solo,phasePolicy}`. Both variants and immutable asset references remain shared; all mutable controls belong to this pattern. Missing old clip roles become disabled variant1/volume1/pan0/mutefalse/solofalse/phasePolicy `continue-source`. The original six-role presence/order is recorded in `compatibility` for a representable old export; missing roles are not made audible. Programme chain is the old ordered **one-bar pattern-ID list**, not root section occurrences.

### Native score programme (kind `instrument-events`)

Exact `{clock,banks,events,instrumentMix,tuningConsent,accompanimentRef}`. Clock, banks, strike/damp IDs/ticks/order/velocity and instrumentMix retain schema4 values. Missing mix is `[]`, meaning the existing per-instrument unity/pan0/no-mute/no-solo default; it does not erase inactive explicit mix entries. Missing tuningConsent becomes false. `accompanimentRef` references a composition definition with parentId=this score ID and parent master binding. This is a real editable source reference, not an opaque render or inaccessible backup.

**Multibar representation:** Gamelan absolute events stay in this one whole score. Its accompaniment definition retains every legacy pattern, all cells/notes, active pattern and the complete ordered A/B/... chain. An accompaniment occurrence at index i starts at `i*4*PPQ`; its step j starts at the existing swung step time within that occurrence. IDs are `(sourceDefId,patternId,occurrenceIndex,role,step)`; edits target original pattern IDs/cells. No16-cell array is expected to hold an entire multibar score. Root section A places the native score at tick0. No repartition or quantization of native events occurs.

`transport={kind,nativeLengthTicks,accompanimentLengthTicks}`: kind `chain|legacy-beatbox|legacy-score|legacy-continuous`; absent lengths represented as null. For schema4 legacy-score keep `nativeLengthTicks=old.clock.lengthTicks` and independently retain `accompanimentLengthTicks=old.composition.chain.length*4*PPQ`. Once duration remains the maximum of native clock, audible accompaniment length and natural/release tails. Current main Gamelan repeat with audible accompaniment still rejects `repeatNeedsEventOnly`. A shorter native clock does not truncate accompaniment. Conversion to new native Rantai Pola is explicit later; no migration invents a different period.

### Sections, placements and root chain

Section `{id,name,lengthTicks,placements}`; placement `{id,trackId,sourceRef,startTick,lengthTicks,offsetFrames,loop,phasePolicy,alignment}`. `sourceRef={kind,id}`, kind `working|asset`; working points to sourceDefs, asset points to assets. For group sources offsetFrames remains0. Length/start/loop keep old region semantics; alignment is null or the exact typed object below. Phase policy `continuous|restart-on-entry`. Root chain entries `{id,sectionId,repeats}`; occurrence IDs differ even for A→B→A.

Initial root section A places the complete imported programme/score in one outer group bus. Schemas0–3 A length is the normalized programme chain length×4×PPQ; schema4 A length is its original native clock, with accompaniment allowed its independent declared span. Legacy0–1 live playback remains continuous regardless of finite export bars. Schema5 A display length is max existing placement end (or4×PPQ if empty); this never becomes a live wrap. New Play/Once/Repeat are explicit ephemeral commands, not a hidden migration of export settings into playback mode. Envelope `export={scope,bars,tailPolicy}`: scope `arrangement|active-section`, bars4/8/null, tailPolicy `full-natural-tail`; preserve0–1 export bars,2–4 bars null (whole accepted arrangement),5 initial4 (old UI default, not a source field). Compatibility presence records that schema5 had no export field.

Legacy schema5 uses `legacy-continuous`, root section A containing its existing placements, `chain:[]`; A's display length is not a new repeat period. Keep every arbitrary clip period/start/offset and optional fixed-bar clock. Imported sourceDefs are independent working states even if immutable origin bytes are shared. Only explicit user cloning shares an original ref while copying mutable state.

## 2. Exact EQ, overdub and alignment mappings

`tracks[].fx={eq}`; eq exactly `{version:1,bypass:boolean,lowDb,midDb,highDb}` with each dB in [-6,6]. Missing schema5 eq maps to existing FLAT_EQ. Preserve explicit bypass and all three dB values even if numerically flat. No baking into PCM, gain normalization, frequency changes or tail loss. Outer bus EQ follows summed clips/layers as today, before outer master/limiter. Existing 0.1s EQ tail and conservative eqBound/resource costs remain. Nested source buses preserve their source gain; no second copy of outer EQ.

`tracks[].layering` is null or `{version:1,basePlacementId,overdubPlacementId}`. Schema5 `baseClipId`/`overdubClipId` map to corresponding unchanged clip/placement IDs with the same order. Enforce exactly two distinct recording assets, identical frames/channels/rate, fixed-bar geometry, complete1/2/4/8-bar periods, startTick0, offsetFrames0, looptrue, recording track kind. Do not flatten, sum, normalize or change their individual audio hashes; Undo removes only the layer and retains pinned base/originals. Future unsupported third-layer edits reject `invalidOverdubLayers` before mutation.

`placements[].alignment` is null or `{version:1,mode:"circular-period",sourceSHA256,advanceFrames}` copied **verbatim** from schema5 phaseAlignment. It is valid only for its matching recording asset, fixed-bar sample rate, looping complete1/2/4/8-bar source, offsetFrames0, frames≥128, and `abs(advanceFrames)<=floor(rate*.25)` and `<periodFrames`. For each raw frame index f read positive modulo `(f+advanceFrames)%periodFrames`; a positive value advances late material. Preserve opposite signs independently for base/overdub. Do not change offsetFrames, raw period, hash, recording window or bytes. Null has zero effect. Explicit zero remains explicit on roundtrip if the old file contained it; ordinary UI may still choose to omit a newly reset zero.

`compatibility` exactly `{sourceVersion,rootOriginId,fieldPresence,rolePresence,idMap}`. fieldPresence records optional field paths actually present; idMap reversibly namespaces legacy origin/source/track/clip/event/pattern IDs. This permits exact semantic inverse including absent versus explicitly flat/bypassed/zero fields. Original download always returns original bytes, never a reserialization presented as the original.

`fieldPresence` is a sorted unique array of source-ID-qualified field paths. `rolePresence` is an array `{sourceId,roles}` retaining each composition's original clip role order/presence. `idMap` is an array `{kind,sourceId,oldId,newId}`, unique in both qualified directions. Stored IDs may use independent source-local namespaces; new display/occurrence IDs never rewrite a foreign source's damp, layer or pattern reference. A reverse projection removes only successor fields and revalidates the old grammar; if changed values/relationships cannot fit, refuse rather than drop them.

## 4. Boundary/phase and mix semantics

Percussion and Bilah mixes are global **within their composition group**. Beatbox control/mix is pattern-owned. Root solo scope is outer buses; composition solo is the current pattern's six Beatbox rows plus that group's eight percussion rows and Bilah, matching current allMix including its disabled-solo edge cases. Native instrumentMix solo remains a third independent source-native scope. A nested solo never silently mutes a sibling outer bus. Outer EQ acts on the whole bus, not independently on each layer.

Source identity for phrase continuity is `{packId,packVersion,processing,role,variant}`. Gain, pan, mute, solo, enabled and control object identity are **not** part of identity. At A→B:

- Same source and `continue-source`: phase is previous anchor advanced by exact elapsed frames modulo the original phrase period (at96BPM, two bars=5s). Gain/pan change uses existing bounded mixer ramps, no voice restart, reset, pitch shift or fresh normalization. Capture master ramps keep their already accepted policy.
- Mute/solo gating keeps a source's phase anchor running; becoming audible resumes at the continuously elapsed phase. Release/rejoin may create a bounded reader at that phase; it does not restart the phrase. Any required outgoing+incoming overlap must pass resource admission.
- `enabled:false` explicitly exits that placement through existing release. On false→true, start a new phrase at zero. Settings retained while disabled remain independent per pattern. This differs deliberately from mute/solo gating.
- Changed source/variant/processing or explicit `restart-on-entry`: new anchor at the boundary, phase0. The outgoing voice retains its established release; no abrupt cut or dropped incoming hit to force admission. A new chain occurrence of identical A is continuous unless restart was explicitly chosen.
- Pause preserves anchor/position. Seek is reconstruction at the destination within the flattened arrangement, not elapsed wall time while paused. Across chain wrap, identical continuing source keeps phase; whole new Play from stopped establishes a new arrangement origin.

Frame conversion uses the accepted MasterClock at each absolute tick, not cumulative rounding of short section durations. Fixed-bar geometry is preserved at its recorded rate; raw recordings do not stretch. Beatbox enabling still requires96BPM. One immutable identity-bound arrangement plan must drive scheduler, feedback and WAV; the bounded primitives initially added for Q1 are not yet wired to these consumers.

## 5. 0–5 mapping, originals and failure contract

0: validate old flat format, packId/version/bpm/volume/layers/exportBars become the same Beatbox programme via existing migration semantics; preserve all raw bytes. 1: same with existing typed pack/timing/master/tracks/export. Both keep continuous live Beatbox behavior; export4/8 bars does not impose a live stop. Source master binds root. New disabled percussion/Bilah state comes from existing validated migration defaults, not invented notes.

2: preserve pack/timing/master/8 mixers,1–16 patterns/steps/activePattern and exact chain/export. Silent Beatbox/Bilah defaults use the existing composition adapter. 3: same plus Bilah notes/global mixer and exact clip pack. Deep-copy the six migrated controls to each pattern. Preserve pack/processing, source origins and optional role presence; editing B cannot change A.

4: one whole native score definition and its composition child, root A, chain[A], exact native/accompaniment lengths and masters described above. Off-grid ticks, damp ownership, IDs, tuning consent, inactive mixers, natural tails and multibar A/B accompaniment remain editable. 5: preserve outer buses/FX/layering/alignment, sources/origins, refs, fixed/musical clock, tuning consent, arbitrary placement starts/periods and gain factors. Import optional-field defaults is distinct from changing an accepted stored value. Root title/master/limiter remain exact.

All old formats are validated by their current strict parser first. Raw originals use SHA256 over original Uint8Array bytes, lowercase hex; byteLength is actual bytes. Files are read using the same legacy UTF8 decode behavior, but the original Blob retains BOM/newlines/invalid-byte replacements separately. Embedded origin `text` is preserved as exact JavaScript string/code units, including whitespace; its UTF8 digest is not misrepresented as the original parent-file digest. Registry refs keep bank/sample versions, attribution/provenance, original hashes and processing hashes separately.

Origin record exact keys `{id,kind,schemaVersion,mediaType,byteLength,sha256,blobRef,text}`: kind `file` has text null and blobRef=sha256; kind `embedded-text` has the exact old string, blobRef=null, byteLength/hash of its UTF8 encoding. File schemaVersion is the parsed old project version (portable has its manifest project version). Assets retain exact schema5 `{id,kind,sha256,bytes,frames,channels,sampleRate,encoding,recordedBpm}` plus `creditsRef` pointing to the immutable credit record. Shipped sample provenance remains in the versioned registry referenced by the working score. Required original/credit blobs are part of save admission; a metadata-only inspection does not claim that originals/audio are durably saved.

New IndexedDB **`perkusi.composition.v6` version1**, stores `documents,blobs,credits,refs,pointers`. Blob key=hash of exact bytes, credits key=`documentId:assetId:hash`, refs identify document/original/history/transfer owners, document key=`documentId:revision`, pointer key=documentId. One readwrite transaction publishes blobs/credits/refs/document/pointer with expected-revision compare; oncomplete is the commit point. No current schema0–5 database/key is upgraded or written. Read old stores only. No PCM in JSON/localStorage; only document ID may be a localStorage navigation hint.

Hash/geometry/credit checks precede pointer promotion. Quota, abort, stale revision, missing/corrupt assets, unsupported optional fields, resource refusal or unknown group retain old accepted document, selected pattern, undo/redo and raw portable file. Staging/pending imports and undo keep refs until actual completion/abort, no foreign-pin release. Missing data opens a recoverable inspection/original-download state; it must not substitute silent buffers or pretend a successful save.

Q1b is metadata parser/migrations only: no user-facing canonical portable export or cross-store promotion yet. Preserve a legacy portable input Blob unchanged and validate its existing PKLOOP01 hashes when supplied. Q3 must implement the canonical package with exact original payload retention and bounded streaming under the current memory tracker before exposing portable save. Until then refuse canonical portable export explicitly; JSON references alone are not a portable recording. Lossless projection back to an old version is validated and offered only when representable. A per-pattern divergence, new native chain or unsupported field produces Preview/Derived copy/Cancel; no silent flatten, defaulting or overwrite of the old file.

## 6. Executable acceptance and next bounded step

### Q1b.1 implementation clarifications

The schema6 JSON parser/validator, metadata migration and fresh legacy projection now exist in `src/project/canonical-metadata.js`, with no active route/store/audio consumer. The object guard in `canonical-data.js` admits up to2000000 visited values /depth64 under the8MiB JSON cap; it deliberately does not use the old50000-node global guard. Each reconstructed old group still passes its unchanged legacy parser/limits. The returned immutable copy breaks caller-supplied object aliases so separate patterns cannot share mutable controls after cloning for edits.

The source-count formula in the earlier planning table is **not** a bound on a repeated arrangement. `canonicalSectionCandidates` sums candidates for **every placement** multiplied by explicitly supplied planning-window recurrences; composition upper counts include six loop starts, and native groups add their event count to the accompaniment count. `planChainExpansion` then multiplies section counts by every root chain occurrence/repeat. The1343488 candidate count is a separate admission cap, not a source-deduplication proof; the8MiB schedule-byte gate still applies first in practice. A dense valid metadata document is retained even if this later planning admission refuses. The32-placement limit is cumulative per outer bus across all sections, not reset per section.

`phraseTransition` accepts `phaseFrame:null` only when the previous control is null/disabled. Returned state composes directly through on ->off ->off ->on; an active continuing source still requires a real cursor. Disable retains no anchor and re-enable starts at0. No caller-invented0 normalization is required.

Q1b import accepts legacy JSON as text, Uint8Array/Node Buffer or a JSON Blob. It checks the old version's strict grammar first, retains a private copy of original bytes (including BOM/replacement-decode cases), and produces canonical metadata. `originals.get(hash)` returns a new copy. Abort before/during staging never publishes a replacement. The pure API neither receives nor changes an accepted UI document/history/store.

Inverse reconstruction does **not** read those external original bytes or start from an old-project clone. It creates new legacy root/track/clip/programme/event records from current canonical values and revalidates the target grammar. Original embedded text is a real legacy field and remains exact. A working-source text may reuse its lexical spelling only **after** a fresh reconstruction compares equal to its parsed semantic content; edits instead serialize the newly reconstructed source. Per-pattern divergence, new section layout/phase policy or an otherwise unrepresentable edit refuses `needsConversion`. Source0–5 original download remains separate from this semantic projection.

`inspectCanonicalAssets` can check supplied original/recording hashes, credits, raw finite Float32 values and current rate/offset/payload caps, with optional caller memory reservations before Blob reads. Missing/corrupt assets/originals/credits are explicit inspection issues; `playableVerified` and `durableSaved` remain false even when issues are empty. No AudioContext decode, database transaction, active storage switch or new portable container is implemented here. Existing legacy PKLOOP01 import/export remains unchanged and regression-tested; this isolated migration entry point consumes JSON metadata, not a binary bundle. Canonical portable export explicitly refuses `canonicalPortableNotImplemented` until the later package/persistence stage.

Deterministic non-legacy defaults are section `a`/name A, bus names `Track N`, schema5 export4 bars, musical PPQ960000 when the old clock was absent, bypass FX/limiter and false outer consent. Compatibility presence preserves whether old optional fields existed, so those defaults do not leak into an unchanged old inverse.

`tests/fixtures/v5-canonical/` pins representative0–5 originals and a schema5 metadata boundary case. `tests/v5-canonical-contract.test.js` checks them using unchanged old validators and independent frame/cell/read-position oracles. Synthetic PCM is generated only in RAM; no new production sound or audio file is created. Existing portable/overdub/EQ/phase/atomic-save tests remain prerequisites.

Q1b metadata validation/migration/fresh inverse and the earlier pure phase/expansion/pattern-control helpers are implemented and remain isolated from active routes, stores and audio. The next bounded stage is Q1c: one immutable arrangement plan with differential legacy live/WAV semantics, multiplicity-aware admission and failure/cancel ownership before Q2 UI or main-Studio integration. Q3 owns durable canonical project/audio persistence and portable packaging. Q4/Q5 add native chains; Q6 consolidates acceptance. No extra build is required for metadata work. Accepted Q0 artifact, preview and production remain untouched; product V6 and publication remain held.

## 8. Q1c.a logical timeline and finite DSP checkpoint

The shared destination remains **the actual main Rhythm Studio**: combined composition, master playback and Pattern Chain. Gamelan/Beatbox create editable instrument/beat material; Loop Station handles recording/overdub. Continuing a lossless document into the main hub is the later integration target. Links to each tool's separate Studio view do not meet that target.

`compileCanonicalTimeline` in `src/project/canonical-timeline.js` directly reads a privately validated canonical snapshot. It does not call the inverse or old sequence/take/Loop planners. Its immutable result is deliberately `status:"logical-only"`; `audioAdmitted`, `playableVerified`, `durableSaved`, and per-source rendering/repeat qualification flags remain false. No active route, scheduler, feedback view, WAV exporter or storage consumer imports it. This checkpoint is not GO for Q2/runtime integration or a complete Q1c acceptance.

The caller supplies the shared `AudioMemory`, registry, rate44100/48000 and an exact command `{kind,bars,cycles}`. `once` uses the imported chain; `repeat` creates an explicit finite reconstruction window of1-8 root cycles under the existing cumulative8-occurrence cap. It does not install an infinite transport or claim repeat-tail/native voice qualification. Legacy Loop instead requires `window` with4/8 bars; its display section never becomes a live wrap. Wrong recorded rate refuses; a nonzero recording offset remains explicit and reports the old playback issue. Every placement, internal source recurrence, root occurrence and six Beatbox control boundaries **per bar** is counted before flattened allocation/reservation. The schedule cap remains8MiB, candidate cap1343488; a separate UTF8 snapshot allowance is reserved in the same memory pool. These are declared resource allowances, not a JavaScript heap/RSS measurement or PCM/native-voice admission.

The plan retains tuple identities (source/local event or pattern/occurrence/bar/role/step), absolute-tick frame conversion, same-tick damp-before-strike lexical event ordering, role-local percussion/Bilah chokes, native release/natural endpoints, independent audible accompaniment span, unchanged bus FX/overdub links and raw recording references/alignment. Source references remain shared immutable objects; mutable caller state and retained original bytes are never borrowed for publication. An idempotent dispose releases only its own logical lease. Cancellation/refusal/concurrent jobs preserve foreign owners and never publish an accepted UI replacement.

`canonicalTimelineAt(timeline,frame)` is a common deterministic query for future scheduler/feedback/render adapters. It reconstructs phrase phase and raw recording position from the arrangement frame; pause does not advance the argument and seek is independent of wall time. It covers per-pattern mix/gate versus enable/disable, variant/restart and identical repeated root occurrences. It is **not** a native live scheduler or proof of bounded outgoing/incoming reader overlap. General continuity between different placement IDs/sections, dynamic4ms mixer ramps, native cross-cycle damping/chokes and terminal repeat tails remain unqualified.

`src/audio/canonical-composition-render.js` is an isolated finite-composition differential kernel. It consumes compiled shots directly and preserves the old finite body/fade/curve policy. Uniform legacy controls are supported; dynamic divergent controls, repeat/loop buses and inherited nonzero phrase anchors explicitly refuse rather than emit a provisional mix. It reserves output/curve bytes before allocation, borrows only trusted already-accounted sample buffers, checks sample geometry/finite data, and releases its own output on failure/cancel/disposal. It does not fetch/decode samples, prove provenance or grant runtime admission. Shared low-level envelope/panner math is intentional; its planner is independent of the old reference renderer.

QA compares original0-3 byte fixtures through the unchanged parser/renderer against the directly compiled timeline, plus both variants/omitted roles/solo/pan cases. Native0-5 frame comparisons use original legacy plans; native-tail PCM uses the common established instrument DSP with independently generated voice specs. Loop PCM compares the unchanged old Loop planner + old composition renderer with **test-only** direct canonical specs + new composition kernel, both through the established final mixer. It includes EQ, overdub, signed alignment, limiter, local/parent/outer masters and4/8-bar lengths. The44.1kHz Loop capture is explicitly a derived synthetic QA specimen with new raw-period metadata/hashes; the original48kHz fixture refuses a44.1kHz playback rate. All synthetic sample/recording PCM stays in RAM and is not production audio or a listening claim. Exact Float32 comparisons use zero-bit tolerance at the named pre-programme taps; they are not encoded final-WAV byte parity or native-live audio evidence.

Remaining Q1c gates: prepared source capabilities and total PCM/decode/FX memory;16 actually owned voices including outgoing tails/lookahead/grace and unchanged0.95 headroom; real native live scheduling versus WAV; dynamic per-pattern ramp/release/re-enable audio; general section/placement continuity, seeks and root wrap; event-only repeat damping/terminal tails and full programme/WAV encoding parity; browser cancellation/replacement/disposal with accepted state preserved. Keep the current accepted artifact/preview/production and all original metadata/audio untouched while these gates are completed and independently reviewed.
# Explicit local hub continuation (2026-10-18)

This successor adds the optional exact root field `mixPolicy: "unified-outer-v1"` for explicitly combined working copies. Existing documents retain their previous grammar and master semantics. Under this policy no source may bind its master to the root: root-bound legacy levels become independent local levels (0..1); parent-bound accompaniment remains parent-bound. One shared outer master then applies to every bus, including recordings. Legacy inverse export refuses this policy; full canonical export preserves it.

The explicit Add material action copies nonempty tracks into the active section, assigns independent source/bus/placement IDs, retains all raw originals and recording PCM/credits, and archives complete canonical input files. It preserves BPM, exact fixed-bar clocks, source periods, phase alignment, EQ and event positions. It refuses unequal tempo, incompatible clocks, more than eight source tracks, an active incoming nonlinear limiter, or a native region shorter than its audible accompaniment. Native duration extension and source-limiter bypass require explicit edits. A continuous Loop input receives the visible four/eight-bar window; its loops follow the resulting section duration. No silent resampling, trimming or master baking occurs.

Portable `PKCAN001` header version 1 remains the output for projects without source archives. Header/manifest version 2 adds an exact `backups` array and hashed `backup` payloads for complete working input files. Originals plus archives remain bounded to 20 MiB, recordings to 16 MiB, and all allocations still share the existing 64 MiB admission pool. Canonical IndexedDB v1 stores archive references alongside each immutable revision; existing records without them remain valid. No legacy store migration or garbage collection is triggered.

Imported recording handles are local project data with their exact provenance. They declare `commercialUse: null` and `rawRedistribution: null`; playback does not fabricate a sample license or authorize promotional distribution. Shipped asset license gates remain unchanged. The UI is enabled only by explicit localhost candidate injection; normal routing and production activation remain held.

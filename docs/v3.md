## Musical model and shared engine

Schema 3 is a strict bounded composition retaining schema 2's eight drum tracks, sixteen-step patterns, BPM 60–180, swing, mixer, undo and pattern chain. It adds up to six known Original Groove vocal loops, immutable pack processing identity, per-loop variation/mix and a sixteen-step Bilah note lane in each pattern. Valid partial/empty clip arrays remain partial until edited; an omitted known role is created with disabled defaults, then only the requested field changes. Existing clips and score content are preserved, and failed edits restore controls from the actual model. Bilah offers D4/F4/G4/A4/C5 and velocity; its native note duration/pitch do not change with BPM.

All voices use the existing AudioContext.currentTime transport and lookahead scheduler. requestAnimationFrame updates visuals only. Clips preserve the original two-bar 96 BPM phrase and mastered Bumi processing, so an enabled clip locks BPM to 96. Loops repeat across the full chain; WAV renders one chain pass. Prefer two/four/six/eight pattern entries for complete two-bar phrases. A one/three/five/seven-entry chain intentionally ends partway through a phrase. The UI explains this and the 4 ms WAV end fade. Default Play follows the chain; choosing pattern preview explicitly prompts before exporting the full chain.

Global solo spans drums, loops and Bilah. Loop center pan preserves the original mono signal in both stereo channels without additional gain. Decode banks share a 32 MiB limit. Export preparation/rendering/retained PCM has a separate conservative 32 MiB peak budget. No arbitrary asset URLs or uploaded sound data are accepted.

## Mode changes and recovery

Beatbox schema 1 maps exactly to schema 3 loop selections, variations, master level and four/eight-bar duration; drums/notes remain empty. Compatible reverse changes preserve the same musical score. A composition containing extra drum/note content, another kit, changed tempo/swing/arrangement/mix requires an explicit derived-copy dialog. Cancel leaves the source unchanged; the derived Beatbox copy keeps only audible compatible original loops and does not resurrect globally solo-suppressed loops.

Before navigation a single bounded localStorage transfer record stores the full original, destination candidate, previous destination draft and deduplicated originals plus every displaced raw destination draft (maximum 30 originals and drafts combined, 256 KiB). A sessionStorage marker contains no composition or URL data. The target validates before applying/acknowledging. Storage denial keeps the user at the source; corrupt incoming data is retained with recovery guidance. Originals and every retained prior destination draft are selectable and downloadable; clearing backups requires explicit confirmation. The bridge accepts existing internal record version 3 and writes internal version 4 with a raw-draft collection. Composition JSON remains schema 3. Quota/count/byte limits refuse new navigation without evicting protected drafts. Legacy/corrupt raw backups are preserved without normalization.

Schema 0/1/2 migrations create schema 3 copies in the Studio store. Legacy stores remain byte-for-byte intact. JSON imports are validated before replacing history; invalid files cannot partially mutate a score. Corrupt startup drafts disable autosaving over the damaged original. Unsaved replacement and conversion cancellation are localized in Indonesian and English.

Page ownership releases timers, animation callbacks, listeners, voices, captures, decoded banks and object URLs. Mode navigation pauses/fades first; pagehide requests native context closure immediately, without depending on a timer that could freeze. The existing single persisted-pageshow handler rebuilds a disposed Studio owner.

## Incoming delivery and later edits

A pending marker is not permission to replay an old copy on every boot. The receiver first finishes ordinary draft restoration (including the asynchronous Beatbox restore), preflights the bounded acknowledgment, and reconciles the current destination draft against the protected baseline/candidate. It refuses an exact-limit unfinishable copy before making it editable. Newer destination work is kept rather than replaced; the transfer copy can be downloaded and explicitly imported if the user chooses to replace that work.

One durable receipt per mode identifies the transfer ID, target, full validated candidate value and reserved/applied/blocked state. Each receipt is capped at 65 KiB (two fixed keys, no growing ID ledger); the existing bridge remains capped at 256 KiB and 30 originals/drafts combined. Receipt identity compares normalized project values, including array content, so JSON key order does not cause a replay. Corrupt or conflicting receipts refuse delivery while leaving current work and bridge recovery downloads available.

Delivery reserves the receipt, writes the validated ordinary draft, applies it under an edit/autosave lock, marks the receipt applied, then acknowledges/removes the matching session marker. If a later write fails, the durable reservation prevents automatic replay. On reload, ordinary draft restoration is authoritative. A reserved copy already present can finish metadata only; otherwise the receiver keeps current work and requests explicit recovery. An applied copy followed by newer edits retries only acknowledgment. Already-acknowledged stale markers are cleaned without applying a candidate or duplicating the conversion event.

These localStorage operations are individually atomic, not a cross-key transaction. Reservation and baseline checks make partial failure fail conservatively without discarding protected originals/raw backups. A changed active transfer is checked again after asynchronous application, preventing stale acknowledgment from replacing another record. Same-handle delivery calls coalesce. Startup autosave timers are suppressed during receipt delivery, and only a validated explicit persisted replacement re-enables autosaving over a formerly corrupt destination draft. Confirmed backup clearing also removes receipts; ordinary current projects remain separate.

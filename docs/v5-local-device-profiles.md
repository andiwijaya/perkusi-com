# V5 opt-in local device offset profiles

PRD §5.3, line 201 of the verified V4–V6 transcription, says “Simpan profile perangkat lokal jika pengguna memilih; jangan unggah device fingerprint.” This is a V5 capability with optional user participation, not a reason to defer all profile support to V6. It does not explicitly require an automatic calibration wizard. The separate hardware-measurement requirement and the conditional wired median compensated ≤25 ms development target (§5.5.3) remain unverified.

For each eligible complete recorded loop in the existing position panel, the user may save the manual draft offset with a chosen short setup name. Profiles always say **manual / UNCALIBRATED**. Loading a deliberately selected profile fills only that clip's draft number; existing Preview and Save position remain separate actions. Track selection refreshes the phase/profile controls for that track. No calibration simulation appears as a measured product result. The 6 ms and −12.5 ms values used in QA are simulated inputs, not default product profiles or device measurements.

Storage uses only `perkusi.loop-station.device-profiles.v1` in the current browser origin's localStorage. There are no writes on construction/empty reads, no auto-selected profile, no automatic audio application on reload, and no device enumeration, device IDs, browser/hardware fingerprint, analytics, network requests or microphone activation. Names are explicitly entered by the user and rendered as text. Up to eight profiles are allowed, with names of at most 48 UTF-16 characters, bounded signed offsets ±250 ms and recording rate 44.1/48 kHz. This recording/context rate is not a measured hardware input rate. A different recording rate refuses to load and leaves the draft alone; hardware/route changes still require user review.

The separate versioned preference format is not part of project schemas, IndexedDB takes, audio provenance, portable bundles or WAV metadata. Loading/removing profiles does not edit clips or originals. Explicitly saving a position continues to use the existing hash-bound per-clip `phaseAlignment` and its durable undo/portable/WAV rules. Old projects and browsers with no profile key behave as before. Blocked/quota-limited storage leaves manual adjustment available and never reports a successful profile save. Unsupported/corrupt profile data remains until explicit clear. Deletion is confined to this key; clear-all asks for a second user action. Both Load and Delete validate the complete displayed selection against the current record, so a recycled slot cannot silently refer to a replacement. A stale selection is refreshed/cleared without changing its draft or deleting the replacement. Observed conflicting writes are reported; this small preference store does not promise a cross-tab transaction or measure acoustic latency.

The original component-only evidence remains frozen in `qa-artifacts/v5-device-profiles-2026-10-17`; independent review accepted its bounded privacy/storage behavior and identified a P3 stale-selection issue. The successor `qa-artifacts/v5-profile-waveform-2026-10-17` fixes that issue and closes **full compiled-workspace UI** with two eligible layers, stale Load/Delete, rate refusal, Preview versus Save, Undo/Redo/reload, separate-profile portable import, ID/EN and 390 px layout. Profiles stay uncalibrated and opt-in. A temporary loopback server was used only for that automated synthetic test and then closed. No physical mic, device permission, external Share/upload or listening was performed. The user-test checklist and requirement/evidence map retain the separate physical gates.

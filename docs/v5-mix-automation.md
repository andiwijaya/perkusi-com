LoopStationSession owns one MixAutomation with a WeakMap per native parameter. Each entry contains only the last owned constant/linear segment's start/end/from/to. Evaluate the held value from that segment before canceling any automation. Never query AudioParam.value to reconstruct pending or current ramps, including initialization and same-quantum changes. Initialization seeds both intrinsic and scheduled values. If a replacement truncates a linear segment, restore its incoming ramp endpoint at the held time before anchoring the new ramp; a set alone would flatten the preceding slope. Every replacement retains the requested20ms duration/target. Graph release clears the segment registry. No external automation writer may mutate these exclusively owned track gain/pan or project master parameters.

Every non-initial controller update proposes one immutable program: sequence/generation, native requested frame, monotonic request walltime, sample rate, common scheduled start, end and grace. The start is max(requested frame + ceil(50ms * rate), prior program start); all gain/pan/master parameters use that same start, their owned held value AT that start, and a20ms ramp. Increasing starts queue/intersect the existing native program. Equal starts coalesce to the final target while preserving the incoming prefix. Earlier starts, stale/consumed proposals and missed starts refuse before admission/publication. Graph initialization remains immediate and seeds intrinsic values. Graph release invalidates proposals and segments.

WorkspaceAudioOwner reserves the conservative old/queued/new endpoint envelope from acceptance until the EXACT scheduled end plus128frames, including the50ms lead. The frontier holds the same immutable program as the session. Admission and a second deadline check precede version/frontier publication; unsafe or pre-admission late proposals change no canonical project, native event, segment, version or claim. Mute/solo are audible gains; crossed stereo pan endpoints retain factor2. Root engine gain remains1. A main-thread AudioContext frame is not native parameter receipt.

A monotonic wall watchdog can conservatively refuse a proposal whose request-to-submit interval exceeds its audio lead while the context is running. Walltime NEVER sets musical timestamps or retimes takes. It cannot establish the freshness of a cached native currentTime on first observation, nor does50ms promise a universal delivery bound. Post-submission deadline/native-call failures become terminal reported faults: cancel/await actual capture closed before stopping ordinary playback, retain the transition envelope until all claims and voices have actually closed/ended, and block further mix/play until graph reload or disposal. This terminal cleanup hold is not additional admission grace. A loaded native full-PCM gate must still demonstrate effective scheduled activation; any discrepancy remains a failure.

Implementation uses supported setValueAtTime/linearRampToValueAtTime/cancelScheduledValues with explicit owned state, without relying on optional cancelAndHoldAtTime or a browser getter interpretation.

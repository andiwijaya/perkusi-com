# S6C2N conservative channel-aware pan admission

Internal repair candidate; capture remains HOLD/unexposed. Signal routing, samples, panners, channelCount/channelCountMode, gain automation, project/engine volume and caps are unchanged. M's center-pan/native dispatcher/original/repeat/ownership proof stays valid.

The actual track gain has explicit2 speaker channels. A mono input becomes two correlated channels before its track StereoPanner, which can sum them onto one side. The previous sqrt2 scalar undercounted this path. The same assumption existed for ordinary per-voice stereo pan and track pan.

`panPeakFactor(channels,pan)` is admission math only. Center uses1. Mono per-voice panning uses1 because no output coefficient exceeds unity. Any non-center stereo panning uses2, the conservative sum of the two absolute per-channel peak bounds. The track stage always uses actual explicit-stereo2; the preceding per-voice stage uses native buffer.numberOfChannels. Older abstract plans without a buffer use the conservative stereo assumption; an actual unsupported channel layout refuses. No correlation, opposite-sign cancellation or RMS credit is taken. Intermediate and nested stereo panners may be overbounded; a refusal reports headroom rather than lowering volume or changing the signal. This minimum bound deliberately trades tighter admission for a simple safe upper bound.

The pan law and speaker upmix distinction are specified by [W3C StereoPanner processing](https://www.w3.org/TR/webaudio-1.0/#stereopanner-algorithm) and [speaker upmixing](https://www.w3.org/TR/webaudio-1.0/#UpMix-sub). The implementation uses coefficient upper bounds instead of a new DSP approximation or a floating-point tolerance.

Capture and ordinary paths use the same helper.

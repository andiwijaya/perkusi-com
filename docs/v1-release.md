## Scope and acceptance

Studio and the remaining three homepage tool cards retain honest upcoming labels.
Six original characters, twelve Original Groove candidates, shared-clock audio,
quantized A/B transitions, Play/Pause/Reset/volume, three-step help, demo, localized
loading/error/retry, keyboard controls and reduced motion form the V1 experience.
There is no microphone, upload, login, database, paid API, saving or export UI.

The source pack deliberately retains `0.1.0-candidate`, `production:false` and
`acceptedVocalBeatbox:false`; the interface discloses the pending listening review.
Those flags describe quality acceptance, not a claim that no candidate assets are
in the bundle. The public build contains twelve candidate WAVs and SVG character
markup; the technical S2 fixture pack and internal lab routes are excluded.

Local evidence is in `qa-artifacts/s5-2026-10-11/`. The S5 report and checkpoint
manifest there identify the exact source, checks, preserved historical failures,
acceptance matrix and deployment constraints. The repaired unit suite has 65 tests.
The former 5 ms wall-clock deadline test now uses the same injected clock as the
other deadline tests: loading at 9,999 ms, timeout at 10,000 ms, successful retry

## Analytics contract and privacy

The existing production-only `G-G9ETDLX4XP` tag and signals/advertising settings are
retained. Frontend events are restricted to `playground_open`, `audio_started`,
`first_layer_enabled`, `three_layers_reached`, `language_changed`, `audio_error`.
Only the language-change event may carry `language: id|en`; other payloads are
empty. Musical milestones occur on the engine's actual playing/active state and
are emitted once per page session. Successful playback requires a running context,
at least one applied active layer and retained voice, and the initial start time
to have arrived. A silent transport with only failed selected assets keeps the
success milestone eligible until Retry produces the first active voice. Recoverable
error transitions can emit again.
No roles, variation choices, patterns, files, project names or invented device
identifiers are sent. Exceptions and blocked loading cannot control audio/UI.
The bilingual privacy text describes this collection. QA uses an intercepted
production hostname and inert/blocked tag; it does not send real GA test traffic.
Live receipt of these new events is a post-deployment verification task.

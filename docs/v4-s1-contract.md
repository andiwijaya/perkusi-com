## Schema 4 and parser isolation

Exactly these required keys, no defaults or optional fields:

```
{format:"perkusi-project", schemaVersion:4, mode:"instrument-events",
 composition:<complete validated schema3 Composition>,
 origin:{schemaVersion:<0|1|2|3>, text:<exact original valid legacy JSON text>},
 clock:{unit:"tick", ppq:960000, lengthTicks:<integer>},
 banks:[{id:<bank ID>, version:<bank version>}],
 events:[{id:<event ID>, tick:<integer>, action:<"strike"|"damp">,
          bankId:<bank ID>, sampleId:<sample ID>, velocity:<number>}]
}
```

All nested records are plain objects with exact keys. No coercion, unknown keys, URLs, tuningHz, parallel beat/frame time or user-take bytes. Native composition fields remain schema3 and retain their complete patterns, notes, tracks, clips, kit/pack recipes, mixer, swing, chain and export settings. Origin is validated using the existing legacy parser; its declared version must match the text. Origin is historical, so subsequent composition/event edits need not equal it. S1 migration freezes both result and input-derived historical data; callers must derive a new document for edits.

Separate `parseInstrumentProject`, `validateInstrumentProject`, `migrateToInstrumentProject` exports; the legacy `parseProject`/`validateProject` stay untouched and reject schema4. No auto migration on load/save. The new parser accepts only schema4; legacy→4 is an explicit operation on text. Input byte limits are UTF-8, before JSON parsing. Migration parses old text within its unchanged 65,536 byte limit, uses existing validated 0/1/2/3→3 migration, and preserves the original text exactly including whitespace. No store writes, eviction, ack cleanup, mutable history/undo/pending action.

Schema4 maximum serialized JSON bytes including final newline: 1,048,576. Origin maximum: 65,536 UTF-8 bytes. Embedded schema3 must still meet its existing 65,536 byte canonical bound. These separate bounds cover a legal full-size legacy input plus wrapper/original escaping and leave bounded room for events; oversized migration must fail atomically without truncation. Test exact limits, whitespace-heavy origins, escape-heavy multibyte origins, and +1 byte rejection.

## Authoritative event time and ordering

PPQ is fixed 960,000 integer ticks per quarter note. All ticks are safe, nonnegative integers; no negative zero. `lengthTicks` is 1 through 491,520,000 (128 bars in 4/4). Events use half-open interval [0,lengthTicks). BPM and meter come only from composition (existing 60–180 and 4/4). Tick positions are already performed positions: existing swing applies to existing step lanes only, never twice to these new events. No tempo map in S1.

Resolution is approximately 1.041667 microseconds at 60 BPM, substantially finer than a frame at 44.1/48 kHz. Absolute frame at a valid context rate is `round(tick * rate * 60 / (bpm * ppq))`, with nearest half-up for nonnegative values, evaluated from absolute ticks rather than rounded repeated periods. Supported rate is integer 8,000–192,000. Frame/context origin is a separate nonnegative safe integer supplied at scheduling time, not serialized in events. Adding it must remain safe. Helpers report frame positions only; they do not schedule/activate transport or imply hardware compensation.

Maximum 4,096 events and eight bank references. IDs match ASCII `[a-z0-9-]{1,64}`; bank versions match `[a-z0-9.-]{1,64}`. Event IDs and bank IDs must be unique. Every event resolves to the exact trusted bank version and sample ID. Strike velocity is finite >0 and ≤1; damp velocity is exactly +0. Canonical sort is tick, then damp before strike, then event ID by ASCII lexical order. Two events at the same tick with the same bank/sample/action reject under the declared single-lane restriction, irrespective of IDs; this is not a general claim about musical ambiguity. Damp plus strike at one tick is legal and damp precedes strike. Distinct samples may share pitch labels: identity remains bank+sample. Unknown/duplicate references reject atomically. Installed older versions remain valid when exactly referenced; newer versions never substitute automatically. No implicit pitch mapping or forged tuning.

PPQ justification: 960000 is divisible by2/3/4/5/8/16, so usual straight/triplet/quintuplet fractions are exact. At60BPM its tick is1.041667us; rounding a capture-frame position to a tick causes at most0.022969frame at44.1k,0.025frame at48k,0.1frame at192k before output-frame rounding. Therefore source-frame to nearest tick to nearest source-frame can preserve frame identity within these supported rates; test it at late128bar boundaries as well as near zero. For128bars the largest integer intermediate tick*rate*60 is5,662,310,400,000,000, below2^53; absolute conversion never accumulates repeated-period drift. One-million-ish PPQ is precision policy, not an audio scheduler interval or claim of microsecond hardware accuracy.

Collision semantics: reject exact same tick/bank/sample/action rather than silently merge/remove one or double its loudness. Distinct ticks that round to the same native frame remain separate events in tick order (then the same-tick damp/strike/ID order); they are not quantized away. Different bank/sample identities at the same tick are legal, including separate articulations with equal pitch labels. Damp targets the referenced sample identity in this foundation; instrument-family/group damper routing is later explicit voice-policy work, not inferred from a pitch label. A renderer must apply the stable order when several operations share one output frame. Adding deliberate multiplicity/layers or broader damp targets needs an explicit later event contract. This rejection is atomic and preserves the supplied original document. Tests exercise the allowed and rejected combinations and stable permutation ordering.

## Three separate asset/data validators

Legacy `validatePack`/`inspectBuffer` are unchanged (2s one-shot/8 stems/4MiB encoded, nonzero and peak ≤.95 admission, existing memory guard).

Trusted instrument bank is explicitly injected, immutable, no fetch/decode on construction. Up to64 installed bank/version descriptors; at most8 references per project. Exact bank keys: id,version,kind=`instrument-bank`,setId,tradition,laras,samples. tradition is a bounded slug carrying a declared evidence category, not proof of authenticity; QA uses `qa-synthetic`. Laras is slendro/pelog/shared/none. 1–256 samples; exact sample keys: id,instrumentId,pitchId,articulation,assetPath,sha256,sourceWorkId,licenseId,encodedBytes,sampleRate,channels,frames,gainTrim,voicePolicy. Slug identifiers bounded64, SHA256 64 lowercase hex, path only `/sounds/` with ASCII safe filename/directory components and `.wav` or `.mp3` extension (no empty/dot/dotdot, percent, query, slash escape, drive, external URL). 1–16MiB encoded, rate integer8–192k, 1–2 channels, positive safe-integer frames with exact decoded Float32 geometry frames*channels*4 <=33,554,432 bytes (32MiB per sample), with no fixed seconds cap, gainTrim finite0–1, voicePolicy `polyphonic`/`choke`/`protected-tail`. Declared format/hash/rights are trusted descriptors, not verified bytes or legal/cultural clearance; acquisition audit remains S2. Resolver exposes frozen copies with exact immutable identity. No bundled production descriptor/QA sound.

The duration derives from complete frames/rate; no trimming, normalization or shortening to fit a duration policy. A known 44.965s stereo recording at44.1k is approximately15.864MBFloat32 and at48k approximately17.267MB, so it fits this per-sample cap unchanged in duration. These are geometry fixtures, not verification of acquired WAVheaders. Sample metadata describes the explicitly expected decoded-rate/frame geometry; acquisition preserves original RIFFgeometry/hash separately. Any native resampling/delivery transform must preserve full duration and retain original identity, with explicit expected output geometry rather than silently relabelling or trimming frames. Samples exceeding per-sample or aggregate budget fail admission without destroying originals; later chunked decode/streaming would require a separately reviewed policy.

Official instrument decoded-buffer validator checks exact frame/rate/channel geometry against descriptor, finite samples, nonzero energy and peak ≤.95. It does not inherit the old two-second limit. Decoder padding/transform must later be explicit; no hidden tolerance in S1.

User-take geometry/PCM validator is independent: rate integer8–192k, channels1–2, frames1 through rate*32, Float32 geometry ≤49,152,000 bytes. Finite PCM with absolute value ≤16 accepted including silence and overrange; return peak/RMS/silent/overrange diagnostics without normalization, clamp, downmix or mutation. The level-limit error is distinct from malformed/NaN/Infinity and is processing admission only; later storage/capture must retain or quarantine finite originals/partials on failure. >16, NaN/Infinity, malformed channel lengths/impossible or excess geometry reject. Limits describe an S1 foundation fixture, not a promise of a full V5 recording ceiling. Count-in/preroll/calibration padding and FXtail rendering are separate from this capture region and must not be trimmed into it. Missing/corrupt actual assets return errors; no placeholder PCM or take persistence. Original buffers remain caller-owned; validation is read-only.

## Aggregate budget contract (foundation candidate, not production qualification)

Default aggregate ledger is64MiB, constructor may choose a smaller positive integer bound but cannot exceed64MiB. It is opt-in and unused by the current engine/cache. Allocation categories cache/decode/render/encoder/capture/undo/fx are mutually exclusive byte reservations; each physical allocation has a unique ID and is counted once even when several owner/pin references share it. Account frame geometry before admission, native pending decode output, retained buffers/tails, render/encoder, IR/ring/undo allocations. Metadata/OS overhead is excluded and explicitly remains a later measured allowance.

Admission/reservation resize/cache-hit revalidation fail without partial mutation when sum exceeds the bound. Cached physical allocations cannot be resized or relabelled. A native completion is terminal: admit actual validated bytes or discard/unpublish output and release its completed logical/native/byte reservation. Unrelated allocations/pins remain unchanged. settle requires a caller discard callback, returns true only on cache admission, false after cancelled-result discard, and throws after terminal discard on invalid/over-budget promotion. reject is only for actual decode/fetch failure completion. Unknown/duplicate completion refuses; allocation IDs cannot be reused. Bounded ledger history permits4096 lifetime admissions; construct a fresh ledger only after existing owners/native reservations are fully settled, never to evade an active budget. Pins prevent release/eviction; undo and pending owners pin originals. At most2 logical tasks and4 native decoder reservations in this ledger, consistent with existing loader. Cancellation of a native decode drops its logical task but holds its byte/native reservation until explicit native settlement; cancelled output is released rather than promoted to cache. Native result replaces its estimate with actual validated geometry after aggregate recheck; a rejected901byte output must never be settled later as fictitious200bytes. Discard callback runs after reservation removal, including invalid output/cancelled completion; callback failure is surfaced with terminal accounting retained. Cache hit rechecks total and geometry; identities cannot alias incompatible sizes. This ledger does not become a parallel loader or relax existing32MiB limits.

## Inert bus/owner hook contract

Standalone opt-in lifecycle adapter, not imported or constructed by current engine/UI/export modules. No AudioContext, getUserMedia, node construction, destination connection, playback request mutation, transport scheduling or storage access. Channels instrument/capture/monitor/export hold independent generation tokens. New explicit begin invalidates and releases prior owned resources. Completion adopts resources only for current token; stale completion releases incoming resources once. All channel resources must have explicit stable release callbacks, one identity per physical resource, reused for duplicate delivery; adapter leases deduplicate that identity even across adapters. A resource already owned elsewhere is refused without releasing its rightful owner. Pause/stop invalidates instrument/capture/monitor; export has separate cancellation. Dispose invalidates all and is terminal. Monitor channel cannot begin without explicit `monitorEnabled:true`; no connection is performed by the adapter. Instrument adoption also requires supplied playbackRequested guard true; capture/export never turn it true. New explicit instrument owner after Play may adopt; no previous token revives.

All affected tokens invalidate before any cleanup callback; begin is refused during cleanup, nested stop/dispose remains safe, guard callbacks are rechecked after reentrant Pause. False instrument playback guard invalidates that owner, so a later explicit Play requires a new owner. Callbacks run after state invalidation; release failures cannot leave stale owners current or skip other cleanup. Untrusted token spoofing and cross-channel adoption reject/release. Fake node/track tests only. Default-path equivalence is ensured by zero imports into existing graph/runtime, unchanged legacy source hashes, old167 tests and final native V1–V3 regression including WAV/PCM.

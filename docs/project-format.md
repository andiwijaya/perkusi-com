# Local projects and audio export (S6 / V1.1)

This local candidate adds project save/load/delete, `.perkusi.json` exchange and 4/8-bar WAV export. It is pending independent review and deployment. The live baseline is `5d91fc4f35b28adb10d39edbc71fda4690e1d6b2`. Android re-audition of its loudness correction is still pending.

## Model and version boundaries

`src/project/schema.js` owns format `perkusi-project`, schemaVersion 1, mode `beatbox`. Canonical fields are title (1–80 sanitized characters), pack `{id,version}`, timing `{bpm,meter}`, master `{volume}`, six tracks `{role,enabled,variant}`, and export `{bars}`. Tracks serialize in official catalog order. Only the exact known Original Groove pack/version, fixed 96 BPM/4/4, official role/variation pairs, volume 0–0.75 and export bars 4/8 are accepted. No user-provided asset URL, audio, code or extra keys are allowed. Imports are capped at 65,536 UTF-8 bytes before JSON parsing, with file size and `.perkusi.json` extension checked before reading.

Explicit version-0 migration accepts only the documented equivalent legacy shape: `{format,schemaVersion:0,title,packId,packVersion,bpm,volume,layers,exportBars}`, where layers contains exactly the six official roles, each `{enabled,variant}`. Newer/unknown versions or modes are rejected without modifying the active composition. There was no existing user project format in the V1 source; version 0 is an explicit tested migration boundary for compatible earlier snapshots, not a claim that a public format previously existed. V2/V3 must add explicit typed migrations and retain these six tracks/pack references; they must not silently strip future fields.

`beatbox-model.js` captures selected intent and validates the complete file before applying. Loading resets to downbeat, retains all saved roles/variations/volume, and leaves playback paused. Files/export represent the chosen mix from bar one, not a recording of timed live button changes. Locale is owned separately by the existing route/localization system, so switching language preserves composition and the ready WAV.

## Storage and local privacy

`ProjectStore` uses `perkusi.projects.v1` (versioned items with unique local IDs), at most 30 projects and 256 KiB. One atomic localStorage write saves or deletes an item. Draft recovery uses `perkusi.draft.v1`, debounced 300 ms and flushed on pagehide/disposal when available. Invalid/quota/denied storage is reported; corrupt data is not silently overwritten. Draft writes stop after failure. Explicit file download/import and audio export continue without persistence. Deleting a saved item leaves the active stage/draft intact; browser site-storage settings remove all local data.

User titles render through textContent/escaped markup. Display titles remove controls/bidi overrides and angle brackets. Download filenames use bounded ASCII slugs and avoid Windows reserved basenames. Imports never fetch assets specified by a file. Official audio requests remain same-origin. Privacy copy describes browser storage, recovery, local import/render, and the selected sharing service's separate policy.

## Renderer, bounds and cancellation

`OfflineWavExporter` shares `SampleBank`, raw/prepared PCM guards, `createLoopVoice`, role trims, Bumi preparation, and the Beatbox output-stage factory with live playback. It has its own job/bank and never changes the live engine or requests microphone permission. It renders mono 48 kHz: 4 bars = 480,000 frames/10 s; 8 bars = 960,000 frames/20 s. `wav.js` emits little-endian PCM16 RIFF with exact lengths, checks finite/nonzero output and peak <=0.95, and never normalizes. The actual Beatbox stage bounds samples to 0.9. Native rendering may differ at floating-point rounding boundaries between contexts; mix comparison/repeat checks allow at most one PCM16 step, not timing drift or audible state changes. Do not promise byte-identical files across browser implementations.

The conservative estimated 32 MiB working budget includes output float PCM, encoder/Blob/File allocations, selected mono decoded assets, reserved live-engine buffers and 4 MiB scratch. It is a bound on planned allocations, not measured browser heap/SPL or a universal device OOM guarantee. At higher live-device sample rates it may reject exports conservatively; the localized error offers a shorter export/another device. Six-role 8-bar export is supported at the tested default 48 kHz. Sixteen bars is intentionally omitted.

Only one export job can run. Loading progress uses completed asset counts, native render progress is indeterminate, encoding progress counts actual samples. Cancellation aborts bank fetch/logical loading and encoder chunks; native decode/render cannot be force-aborted portably. Job ownership persists until outstanding native work settles, cancelled PCM is discarded, and subsequent jobs cannot overlap it. Finalization stops/disconnects voices, master/stage and banks. Disposing the page cancels export and ignores late UI publication.

`FileDelivery` generates only internally created blob URLs for downloads, revokes them after dispatch or immediately on disposal, and validates filenames. A ready WAV is a File. Clicking Share checks `navigator.share` and `navigator.canShare({files:[file]})` at runtime and dispatches within that click's activation; it never awaits a new render first. Unsupported/failed share falls back to download plus honest instructions; AbortError leaves the WAV available without an unwanted download. No WhatsApp/music/sticker delivery promise or composition URL encoding is provided.

## Studio schema2 dispatch (V2)

Studio extends the common `perkusi-project` format with eight mixed one-shot tracks, versioned kit, BPM60–180/4-4/swing/quantize, up to16 named16-step patterns, activePattern, and1–8 pattern IDs in the chain. `export.arrangement=true` renders one frozen chain pass to stereo48kPCM16. Fields, ranges, unknown kits, orphan IDs, extra URLs and future versions are strictly rejected. Shared64KiB input and30-project/256KiB storage limits remain. The common store uses separate Studio index/draft keys so Beatbox schema1 saves remain byte-safe. Historical Beatbox schema0→1 remains unchanged. Cross-mode conversion is deliberately deferred to S9 with explicit unsupported-mode copy, not silent migration/data loss. See `docs/studio.md` and `src/project/studio-model.js` for complete bounds.

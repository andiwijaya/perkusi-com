# V5 S5: local looper/capture contract for review

Baseline production/main remains `9a7f4a38e720639b8a6a70276bada0f127156f25`. S5 is an opt-in prototype and is not imported by production entries. No microphone permission/header change, commit/push, deployment, dependency or Library upload is included. Owner testing can continue while V5 develops. S6 awaits review of this checkpoint.

## One clock and ownership

`LoopClock` accepts the existing `Transport` and actual context. All arm/close boundaries are absolute rounded context frames, never accumulated UI ticks. Count-in is0/1/2bars, recording1/2/4/8bars, with a32second capture window bound. A fixed stored frame period can differ from the ideal irrational-tempo grid; report that drift separately from exact stored-period repetition. No source retiming/stretching is hidden.

`CaptureSession` takes that clock, the same `AudioMemory`/`TakePool`, a caller-owned safe master bus, and a compiled self-origin worklet URL. It creates no AudioContext, calls no getUserMedia/resume, and closes no shared context. `armed/recording/looping/partial/closing/closed/error` states describe audio-thread starts and receipts. A completed capture repeats at its exact end frame inside the worklet, independent of main-thread receipt delay. Caller is responsible for track gain/headroom/limiter routing; there is no live input-monitor path. Musical endpoint crossfade, re-record atomic switching and full mixer/FX UX remain S6, not a claim of click-free live vocal loops here.

The audio thread holds one bounded full float window. It copies at most4096frames per message, at most two PCM chunks in flight. The main thread owns a second pre-reserved full window, copies validated contiguous chunks, then adopts/transfers that storage into a private immutable-original TakePool. The worker copy remains reserved while its loop is alive; chunk/node allowances are also reserved. Raw finite float overrange and silence are retained, not normalized or clamped. Input channel mismatch, missing input, invalid PCM or frame gap terminate an explicitly partial prefix instead of padding.

On ordinary stop, pending chunks flush/ack before worker release. On context suspend, already acknowledged PCM is immediately recoverable; unacknowledged tail is not claimed recovered. The worker reservation remains until a closed acknowledgment, processor termination or context close. This is memory-only recovery, not crash/reload/powerloss durability. S7 must add durable journals/storage.

If main-thread take adoption fails after normal capture completion, the controller immediately disconnects only its own output and requests its worker to stop. The outcome retains `takeAdoptionFailed` and the original capture reason. Its worker lease remains held until the same close/termination acknowledgment; earlier loops, takes, foreign allocations and the shared context remain owned by their existing callers. Regression evidence is in `qa-artifacts/v5-s5-adoption-repair-2026-10-15`; the earlier S5 review HOLD is not retrospectively relabeled as accepted.

TakePool hides the adopted original buffers and detaches caller aliases. LayerHistory supports8track identities, immutable replacement/overdub layer references,32undo entries and redo; history pins original/redo takes. Partial takes need review before ordinary layer commit. Live routing of those history decisions, count-in visuals, play/overdub UI and device-adaptive track controls belong to S6. The S6 controller must stop/finalize active captures before transport pause/tempo change/mode switch; this low-level adapter does not intercept arbitrary external mutation of the existing Transport.

The unchanged shared64MiB admission budget is not total browser/OS RSS. Eight short tracks are measured; eight maximum-duration stereo takes/undo at high hardware rates are not certified. A32second stereo capture at192kHz cannot fit both copies under that budget and refuses before arming. S7 streaming/cache/storage and actual hardware benchmarks must resolve long-take capacity; this is not permission to cut the final8track/8bar requirement or enlarge limits blindly.

## Schema5 and compatibility

The new standalone parser uses `perkusi-project`, schemaVersion5, mode `loop-station`. It bounds timing/master, event/recording/hybrid tracks, tick clip regions, source refs and recording float32le hash/geometry/BPM metadata. Recording audio is external; no local Windows paths, raw/base64 audio or new localStorage schema is introduced. Recorded/embedded prepared-loop tempo is locked unless a later explicit retiming policy exists. Recording identity does not prove the referenced bytes are available: S7 must validate content hash, durable writes and portable import atomically.

V1–V4 migration archives exact original JSON text and places the complete validated source in an event-project clip. It preserves full embedded composition/banks/events/mix/laras metadata, without pretending individual legacy tracks are already converted to native live clips. The existing V1–V4 parsers/default loaders are untouched and reject schema5. Rendering/import UI adapters and actual portable project/WAV integration remain S6/S7. Never silently reverse a changed V5 project to a legacy subset.

## Microphone boundary

`MicInput` requests only after explicit userGesture plus actual user-activation check (test providers inject their own activation). It includes only advertised supported Music constraints, as ideal rather than exact requirements; unknown support uses browser defaults and negotiated non-identifying settings are retained. No device ID/group ID is persisted. Constructor does nothing; denied/unavailable, pending late grant after close, track-ended and context suspend release owned streams/nodes/listeners. Stop Mic must be wired visibly in S6. Incomplete/missing channel settings require deliberate configuration/probing; no implicit stereo-to-mono repair is applied.

Current production `microphone=()` is unchanged. A future V5 mic release needs a narrowly reviewed self-origin allowance on intended recording routes, taking header merge/deny precedence into account, and actual deployed permission/gesture/stop receipts. That change must be explained/reviewed before implementation. No real mic, hardware roundtrip, latency compensation, Safari or physical listening claim was made by these generated-stream benchmarks. `baseLatency`/`outputLatency` are not full input/output roundtrip.
